# 新疆 6 天 5 晚 + 贵阳 1 日旅行执行网站

本项目是一个面向旅途中实时查看、执行和调整行程的网站。核心目标不是单纯展示旅游攻略，而是把每天的路线、住宿、票务、预算、驾驶提醒、风险备选方案和现场执行清单集中在一个移动端友好的页面中，方便两人自驾旅行时随时查看下一步该做什么。

## 当前版本

当前已实现 Flask v1：

- 手机优先的今日看板、Day1 详情、账本、预订与采购、AI 助手页面
- 使用 `data/trip.json` 保存行程、预算、预订、采购和记账数据
- AI 助手接入 DeepSeek OpenAI-compatible API，只生成变更预览，确认后才写入 JSON
- API key 不写入代码，通过 `DEEPSEEK_API_KEY` 环境变量或本地 `.env` 文件配置

## 行程内容维护约束

本项目服务真实旅途执行，不接受只有形式、没有现场决策价值的攻略。任何行程修改都必须同时回答：怎么走、几点走、为什么这样玩、现场怎么取舍、出问题怎么跳过。

### 内容准源

- `data/trip.json` 是网站展示和 API 的唯一行程数据准源。
- `content/dayX.md` 是对应 Day 页底部的备用说明，不能和 `data/trip.json` 矛盾。
- `plans/dayX.md` 是后续维护和复盘用的计划文档，必须同步关键路线、餐厅、住宿、取舍结论。
- `bookings`、`budget`、`supplies` 等运行态记录如果受影响，也要同一轮更新。
- README 只保留项目介绍和维护规则，具体每日执行内容以 `data/trip.json` 为准。

### 每日行程写法

- 每天顶部优先放一条完整百度地图总路线，不要拆成一堆孤立地图点。百度地图起点和终点之间最多增加 5 个途经点，路线链接必须能在百度地图中显示真实驾车路径。
- 每个重要 POI 要写清楚真实导航名称、停留时长、游玩目的、跳过条件和替代方案。
- 餐厅不能只写“附近吃饭”。一旦确定餐厅，必须写入店名、从当前住宿或路线节点过去的百度地图距离/时间、推荐点法、预算和兜底方案。
- 小红书结论要转化成可执行规则，例如“喀赞其主玩，六星街只做甜品轻逛”“松树头只走短版，不走三小时深爬线”。
- 页面展开内容必须同步更新，不能只改摘要卡片；用户在 `/day/dayX` 展开后看到的内容必须是最新版。

### 信息检索流程

- 小红书用于判断“怎么玩才有灵魂”：用明确关键词检索，例如“伊宁半日游”“那拉提镇美食”“赛里木湖东门进南门出”，至少打开多篇真实笔记和评论，记录标题和共识。
- 小红书只作为体验参考，不直接当地图事实。遇到美食、住宿、景点位置时，必须再用百度地图核验 POI。
- 百度地图用于确认路线、点位和距离：优先使用用户提供的短链或完整 `/dir/` 链接；没有现成链接时，通过百度地图搜索真实 POI，再生成完整路线链接。
- 如果百度地图路线看起来是直线、绕错门、先到终点再回头，必须重新增加途经点或调整顺序，直到显示真实驾车路径。
- 对每个候选餐厅或住宿，需要和当天实际住宿/出发点比较距离，不能只说“近”或“方便”。

### 修改后验证

每次改旅行计划后至少执行：

```powershell
python -m json.tool data\trip.json > $null
rg -n "旧餐厅|旧住宿|旧时间段|旧路线关键词" data\trip.json content plans
$env:PYTHONPATH='.'; pytest -q
```

并用 HTTP 或浏览器检查：

- `/day/dayX` 是否显示新时间线、展开内容、地图和预算。
- `/itinerary` 是否显示新的日卡摘要。
- `/bookings?day_id=dayX` 是否同步餐厅、酒店、票务等运行态记录。

如果 HTTP 输出已更新但浏览器仍旧，优先提示用户 `Ctrl+F5` 强刷，或给带版本参数的链接，例如 `/day/day3?v=update-name`。


## 早期每日执行清单草案

以下内容是项目早期 MVP 草案，用于理解最初的网站意图，不再作为当前行程准源。后续维护每日路线、餐厅、住宿、地图和预算时，必须以 `data/trip.json`、`content/dayX.md`、`plans/dayX.md` 和网站页面为准。

### Day 1：6 月 11 日，乌鲁木齐 -> 奎屯

核心任务：

- 12:30 抵达乌鲁木齐天山机场
- 13:00 办理租车，拍摄全车验车视频，包括轮胎、轮毂、底盘、车顶
- 市区午餐，可选托克逊老四号餐厅或楼兰秘烤
- 超市采购矿泉水、功能饮料、馕、自热食品、零食、水果、湿巾、垃圾袋、手机支架
- 前往奎屯，途中可在石河子服务区休整
- 傍晚前往安集海大峡谷看日落
- 晚餐可选俭寨奎城味到大盘鸡、王飞沙湾大盘鸡

预算参考：约 775 元

### Day 2：6 月 12 日，奎屯 -> 赛里木湖

核心任务：

- 早上在奎屯加满油，注意新疆加油站通常需要身份证
- 中午抵达赛里木湖东门
- 提前通过“赛里木湖景区”公众号实名预约
- 自驾环湖路线：月亮湾 -> 亲水滩 -> 克勒涌珠 -> 点将台 -> S 弯 -> 松树头
- 可选择景区内毡房营地或清水河镇住宿
- 傍晚二次进湖看日落

预算参考：约 860 元

### Day 3：6 月 13 日，客之家 -> 晃晃村 -> 果子沟 -> 清水河 -> 伊宁

核心任务：

- 早上从霍城客之家民宿出发，先去 12 公里外的晃晃村看花
- 晃晃村只做薰衣草轻停 30 分钟，普通车不硬进后山土路
- 上午前往果子沟大桥观景台，按登顶版预留 90-110 分钟
- 果子沟后在霍城县清水河镇午餐，主选炭火兄弟烧烤或四十九丸子汤
- 下午进入伊宁，喀赞其 / 伊犁老城短看蓝墙、木门和生活感
- 傍晚游览六星街，冰淇淋、咖啡和彩色街景收尾
- 晚餐安排伊宁夜市或烤肉

预算参考：约 530 元

### Day 4：6 月 14 日，那拉提一整天

核心任务：

- Day3 已住伊宁，Day4 早上从伊宁出发去那拉提
- 那拉提草原需提前在“智游那拉提”预约
- 游玩重点：空中草原、游牧人家、正规马队骑马、盘龙谷道、河谷草原
- 晚上回那拉提镇吃饭，继续住那拉提
- 不再赶巴音布鲁克，不抢九曲十八弯日落

预算参考：约 974-1,440 元，骑马按可选项浮动

### Day 5：6 月 15 日，独库公路北段

核心任务：

- 出发前必须确认独库公路通车状态
- 路线：那拉提 -> 乔尔玛 -> 独山子 -> 奎屯
- 途中经过哈希勒根达坂，可能遇到积雪和低温
- 乔尔玛烈士陵园停留
- 北行途中根据安全条件在观景台停车拍照
- 抵达独山子大峡谷和独库公路起点
- 晚上返回奎屯住宿

预算参考：约 510 元

备选方案：

## 关键风险与提醒

### 独库公路通车状态

独库公路是本计划中最关键的不确定因素。当前行程时间为 6 月 11 日至 6 月 16 日，Day 5 计划行驶独库公路北段，时间卡在每年通车节点附近。

网站需要在行前和旅途中突出提醒：

- 出发前一周关注“平安独库”公众号
- 必要时拨打 12328 交通运输服务监督电话确认
- 如未通车，切换到 Day 5 绕行方案

### 加油与证件

- 新疆加油站通常需要身份证和人脸识别
- 副驾可能需要下车等待
- 建议每天出发前加满油
- Day 4、Day 5 路线长，加油站间距大，需要重点提醒

### 驾驶安全

- Day 4 和 Day 5 驾驶时间长，需保证睡眠
- 山区和独库路段不抢时间，不疲劳驾驶
- 每 1.5-2 小时停车休息
- 遇到积雪、落石、施工、限行，优先保守处理

### 离线能力

- 出发前下载新疆全境离线地图
- 网站核心行程信息应支持离线查看
- 重要酒店、景区、机场、租车点信息应提前缓存或截图

### 衣物与装备

- 墨镜、帽子、防晒霜必备
- 独库达坂可能低温或遇雪，准备冲锋衣或薄羽绒服
- 车内常备水、干粮、垃圾袋、湿巾、充电线、手机支架

## 网站 MVP 功能

第一版网站建议优先完成以下功能：

1. 首页今日看板
   - 当前日期对应行程
   - 下一站、下一件事、预计出发时间
   - 今日驾驶距离、驾驶时长、住宿地点
   - 今日预算和重点风险

2. 行程日历
   - Day 1 到 Day 6 + 贵阳 1 日
   - 每天的时间线、地点、餐饮、住宿、门票、费用
   - 支持快速切换日期

3. 地点与导航
   - 每个地点记录名称、类型、城市、备注
   - 预留导航链接字段
   - 酒店、景区、机场、餐厅分组展示

4. 预订与核查清单
   - 酒店是否已订
   - 景区票是否已预约
   - 租车、还车、加油、证件检查
   - 独库通车状态核查

5. 预算追踪
   - 展示预算项、预计金额、实际金额
   - 自动计算剩余预算
   - 标记超支项和可节省项

6. 应急与备选方案
   - Day 5 独库未通车绕行方案
   - 重要电话和备用操作
   - 低油量、弱网、晚到、景区关闭等场景提示

## 推荐页面结构

- `/`：今日行程看板
- `/itinerary`：完整行程
- `/itinerary/day-1` 到 `/itinerary/day-6`：每日详情
- `/guiyang`：贵阳 1 日
- `/budget`：预算与实际花费
- `/bookings`：酒店、门票、租车和航班信息
- `/risks`：风险、备选路线和应急清单

## 开发优先级

### P0：旅途中必须可用

- 今日行程看板
- 每日时间线
- 关键提醒
- 预算总览
- 独库备选方案
- 移动端适配

### P1：提升执行效率

- 预订状态管理
- 实际花费记录
- 地点导航链接
- 离线缓存
- 每日拍照机位提醒

### P2：体验增强

- 地图视图
- 自动天气提醒
- 路况状态更新
- 多设备同步
- 旅行结束后的照片和账单复盘

## 项目定位

这个项目最终应当是一个“旅途执行中控台”：

- 出发前，用它检查票务、酒店、路线和预算
- 旅途中，用它判断下一站、下一笔花费、下一项提醒
- 出现变化时，用它快速切换备选路线
- 旅行结束后，用它复盘实际花费和体验

第一版不需要做成复杂平台，先把这次新疆和贵阳行程跑顺。只要手机打开后能在 10 秒内回答“现在该去哪、要花多少钱、有没有坑”，它就是成功的。
